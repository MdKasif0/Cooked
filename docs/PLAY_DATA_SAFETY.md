# Google Play Data Safety Questionnaire Guide: Cooked

This document contains the exact responses to enter into the Google Play Console **Data safety** questionnaire for **Cooked** (`com.cooked.app`).

---

## 1. Data Collection and Security Overview

| Question | Answer | Details / Rationale |
| :--- | :--- | :--- |
| **Does your app collect or share any of the required user data types?** | **Yes** | Technical crash logs only (via Firebase Crashlytics / Google Play Vitals). Zero user task content is collected. |
| **Is all of the user data collected by your app encrypted in transit?** | **Yes** | Any diagnostic/crash reports use HTTPS/TLS 1.3. |
| **Do you provide a way for users to request that their data be deleted?** | **Yes** | In-app data deletion button (Settings > Data & Backup > Delete All Data) wipes all local data. All local app data is also erased on uninstall. |
| **Does your app allow users to create an account?** | **No** | Cooked is 100% account-free. No email, password, or sign-up is offered or required. |

---

## 2. Data Types Breakdown

### A. Personal Info (Name, Email, Address, Phone, etc.)
- **Collected?**: **No**
- **Shared?**: **No**
- *Explanation:* Cooked never collects or requests user names, email addresses, phone numbers, or user IDs.

### B. Financial Info (Credit card, bank details, purchase history)
- **Collected?**: **No** (Handled directly by Google Play In-App Billing / RevenueCat)
- **Shared?**: **No**
- *Explanation:* Subscriptions and purchases are managed directly by Google Play Billing. Cooked never receives or touches raw credit card or banking information.

### C. Messages & Personal Notes (SMS, emails, in-app messages)
- **Collected?**: **No**
- **Shared?**: **No**
- *Explanation:* User reminders, deadline descriptions, notes, and checklist steps are stored exclusively in the local Room SQLite database on device. They are NEVER sent to any remote server or collected.

### D. App Info and Performance (Crash logs, diagnostics)
- **Collected?**: **Yes**
- **Shared?**: **No**
- **Is this data collected or shared?**: Collected
- **Is it processed ephemerally?**: No (stored for crash investigation)
- **Is this data required or optional?**: Optional (diagnostics)
- **Why is this data collected?**:
  - `Analytics` (diagnosing crash rates and app stability)
  - `App functionality` (identifying bugs and ANRs across OEM hardware)
- **Data Types under this category:**
  1. **Crash logs**: Stack traces and OS exception details.
  2. **Diagnostics**: Device model, manufacturer (e.g. Xiaomi, Samsung), Android OS version, memory state at time of crash.

### E. Device or Other IDs
- **Collected?**: **Yes** (Installation ID generated by Google Play / Firebase for crash reporting deduplication)
- **Shared?**: **No**
- **Purpose**: App functionality & analytics. Not linked to any user identity.
